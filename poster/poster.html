역경매 승차 호출의 기상 할증을 위한 조회 위치 선정과
요청 간 공유 가우시안 프로세스 기반 API 호출 절감

Reducing Weather-API Calls for Reverse-Auction Ride Fares via Query Placement and a Shared Gaussian Process

장원준 · 권구태 경북대학교 컴퓨터학부

1. 서론

  • 기상 할증에는 출발지 한 점이 아니라 경로 전체의 강수가 필요하다.
  • 기상 API는 조회 좌표마다 호출 1회 이상으로 센다. 경로 위 지점을 균등 간격으로 조회하면 같은 셀을 중복 호출하고 일부 셀은 놓친다.

개념도(가상 경로): 같은 경로를 지점으로 조회하면 셀을 중복·누락하고, 셀 단위로 조회하면 빠짐없이 한 번씩 조회한다.

  • RQ1오차를 좌우하는 것은 보간인가, 조회 위치인가?
  • RQ2GP 분산 기반 배치는 호출을 얼마나 줄이는가?
  • RQ3그 이득은 어디서 오며, 새 자료에서도 유지되는가?
  • RQ4동시 요청 사이에서도 GP가 단순 규칙보다 나은가?

2. 제안 시스템

  • 승객이 거래를 열면 여러 기사가 동시에 호가하고, 승객은 가격과 픽업 시간을 보고 고른다(역경매).
  • 흥정 규칙 13개는 Redis Lua 스크립트 한 벌에서 원자적으로 실행된다. 예: 양보 방향으로만 가격 변경, 동시 수락 중 하나만 체결.

3. 경로 기상 기준가와 조회 위치

  1. 경로가 지나는 기상 격자 셀 U개를 찾는다(9km 격자).
  2. 그중 k = ⌈U/2⌉개 셀만 골라 예보를 조회한다.
  3. 나머지는 GP로 보간해 경로 평균 강수 r과 불확실성 s를 얻는다.
기준가 P = ₹18 × d × S × β(r, s)
β = 1 + min(max(r − 0.5s, 0) × 0.15, 0.5)

d 경로 거리(km), S 수급 할증. 예(데모): 경로 강수 1.020mm/h, 불확실성을 반영한 할증 ×1.123. 상수와 평가 계획은 결과를 보기 전에 동결했다.

조회 위치 규칙(같은 k개): B1은 균등 간격 지점, M2는 절반은 균등 셀·나머지는 지점 사후 분산 합이 가장 큰 셀, Mid는 경로를 k등분한 각 구간의 가운데 셀.

k = 4의 예(개념도). ×는 이미 조회한 셀의 재조회.

  • GP 분산으로 고른 M2: B1 대비 같은 호출에서 오차 −34%, 같은 정확도에서 호출 −26.3%.

5. Mid 규칙과 실시간 검증RQ3

위치를 미리 정하는 일괄 조회에서 고정한 GP의 사후 분산은 관측값과 무관한 기하 점수다. 이 분석에서 나온 계통 표집(Mid)이 M2보다 나았다(사후 비교).

이를 확인하려고 서비스 조건 그대로 출발 시각의 최신 예보를 2026.10.18~11.17에 매시 수집했다(PC가 꺼진 시각 제외). 검정은 수집 전에 고정했고, 평가는 한 번만 했다.

사전 등록 검정 모두 지지: Mid < M2 < B1
(Holm p = 3.5×10⁻⁴, 1.2×10⁻¹¹). 세 자료에서 순서가 같다.

6. 요청 간 공유 GPRQ4 · 시뮬레이션

다른 요청이 캐시한 셀 값을 2차원 GP로 빌려 써서 새 요청의 조회를 줄인다. 벵갈루루 검정은 같은 호출 조건에 실패(호출 1.07배)해, 규칙을 고정하고 처음 쓰는 도시(하이데라바드)에서 호출 수를 맞춰 재검정했다.

같은 호출에서 공유 GP의 오차가 이웃 규칙보다 36%, 고정 예산보다 64% 작다(Holm p < 10⁻⁸).

요청당 호출(전체 요청 흐름, 사후 집계): 이전 방식보다 88% 적다.

8. 결론

  • RQ1셀 단위 조회로 호출 −38.3%. 오차는 조회 위치가 정한다.
  • RQ2M2: B1 대비 오차 −34%(같은 호출), 호출 −26.3%(같은 정확도).
  • RQ3Mid가 새 기간·예보·실시간 예보에서 모두 우수.
  • RQ4공유 GP: 같은 호출에서 이웃 규칙 대비 오차 −36%, 이전 방식 대비 호출 −88%(오차 0.027→0.033).

한계 참값은 분석·예보 자료의 전수 조회(관측 아님), 배치 실험은 단일 도시, 요청 흐름·봇·담합은 시뮬레이션.
향후 Mid·공유 GP의 서비스 적용, 실사용·다중 서버 검증.
