# 공유 GP 두 번째 도시 재현 실험 — 호출 정확히 일치 (사전 등록)

작성 2026-10-16. **이 문서와 `PartB/training/city_replication.py`를 커밋한 뒤에** 새 도시의 날씨를 내려받고, 실험을 한 번만 실행한다. 결과가 어떻게 나와도 그대로 보고한다. 1차 제출 논문과 무관한 후속 연구다.

## 1. 왜 다시 하나 (공개 사항)

- 공유 GP 사전 등록 실험(docs/shared-gp.md, 1dc0814)은 **불통과**였다. 새 기간에서 G의 오차는 이웃 규칙보다 33% 낮았다(Holm p = 8e-13). 그러나 G가 호출을 1.066배 써서 미리 정한 1.05배 조건을 넘었다(findings §32.31).
- 벵갈루루 새 기간 자료는 이미 봤다. 같은 자료로 설계만 바꿔 다시 검정하면 "될 때까지 돌리기"가 된다. 그래서 **한 번도 쓰지 않은 다른 도시(하이데라바드)**에서, 호출 수 문제가 구조적으로 생기지 않는 설계로 **한 번만** 재현한다. 이번에도 불통과이면 이 방향은 여기서 멈춘다.
- 설계 확인(커밋 전, 이미 탐색에 쓴 **벵갈루루 검증 분할**로만): 이 문서와 같은 설계를 창 300개로 돌렸다. N = 20, 목표 0.5에서 G 0.0306, N 0.0489, P 0.0864(호출 모두 0.803). N = 50에서는 G 0.0252, N 0.0237로 G가 약간 나빴다. 결과 파일은 `results/shared_gp_feas/symmetric_val/`. 처음 초안은 비교 대상만 새 도시의 오차로 최선 설정을 고르게 했으나, 공정하지 않아 위 설계로 바꿨다.
- 커밋 전에 한 일(날씨 값은 보지 않음): 하이데라바드 격자 셀 좌표 확인(78개, 최근접 중심 대응 59/60), ORS 경로 150개 생성(U ≥ 3 비율 0.727). 코드 확인은 벵갈루루 검증 자료로만 했다(`smoke`).

## 2. 새 도시 설정 (고정)

- 도시: 하이데라바드. 내륙 도시이고, 남서 몬순이 있으며, 바다 셀이 없어 벵갈루루와 조건이 비슷하다. 영역은 중심 (17.385, 78.4867) 기준 벵갈루루와 같은 0.6° × 0.6°. ECMWF IFS 셀 78개.
- 경로: 허브 10곳(가중치 3/2/1, 벵갈루루와 같은 방식), 길이 층 5–15·15–30·30–60 km 각 50개, seed 2028, 500 m 간격, ORS. 파일은 `PartB/data/hyderabad/`.
- 날씨: 2024-06-01 ~ 2025-11-30 시간별 강수(몬순 두 번, 벵갈루루 두 번째 수집 기간과 같음). 셀당 1회 요청.
- 요청 흐름: docs/shared-gp.md §2와 같다(우천 시간 현지 06–23시, 300개 창 × 10분, 경로 균등 추출, 창 시작 때 캐시 비어 있음). seed = (20261018, N). 이 도시 자료 전체를 평가에 쓴다(분할 없음).

## 3. 방법 (고정, 이 도시에서 조정하는 매개변수 없음)

- **G 공유 GP**, **N 비GP 이웃 규칙**, **P 고정 예산 + 캐시**, **F 전체 캐시**: `training.shared_gp`의 절차와 같다.
- G의 공간 GP 초매개변수는 **벵갈루루 학습 분할 값 그대로** 쓴다(σ_f 0.2766, 길이 척도 23.32 km). 새 도시에서 다시 적합하지 않는다.
- 설정 격자: G τ 0.005~0.500(100개), N은 r 4개 × d 8개 = 32개, P는 ρ 0.05~1.00(20개). 모든 방법에 F(전부 조회)도 설정 하나로 포함한다.

## 4. 호출 정확히 맞추기 (모든 방법에 같은 규칙)

- 목표 호출 = 0.5 × F의 요청당 호출(같은 창들 기준).
- **규칙 모양은 벵갈루루에서 정한 대로 고정**한다. G는 벵갈루루 GP 초매개변수, N은 반경 r = 19 km(벵갈루루 검증 선택).
- 새 도시에서는 방법마다 **호출 손잡이 하나**만 둔다(G τ, N d, P ρ). 그 손잡이의 설정들을 **호출 수만 보고** 정렬하고, 목표를 사이에 두는 두 설정을 섞은 정책으로 평가한다. 섞는 비율 w는 w·호출_a + (1−w)·호출_b = 목표가 되게 정하고, 창별 오차도 같은 비율로 섞는다. 세 방법 모두 평균 호출이 정확히 목표와 같다.
- **어떤 방법도 새 도시의 오차를 보고 설정을 고르지 않는다.**
- 목표까지 호출을 줄일 수 없는 방법은 호출이 가장 적은 설정을 쓰고 표시한다(기술 통계에서만 생길 수 있음).

## 5. 검정과 판정 (결과 전에 정함)

| 이름 | 비교 (N = 20, 목표 0.5 × F) |
| --- | --- |
| R1 | G − N 창 평균 절대 오차 |
| R2 | G − P 창 평균 절대 오차 |

- 분석 단위는 창(MAIN 유형 요청이 있는 창). 양측 Wilcoxon 부호순위, 두 검정에 Holm 보정. 평균 차이 95% 구간은 ISO 주 블록 부트스트랩(B = 2000, seed 42).
- **통과** = R1·R2 모두 Holm p < 0.05이고 평균 차이 < 0. 호출은 구조상 같다.
- 하나라도 어기면 불통과. 불통과이면 공유 GP 방향은 여기서 멈추고 결과만 보고한다.

기술 통계(검정 없음): N = 20에서 목표 비율 0.25·0.75, N = 5·10·50에서 0.5. 벵갈루루에서 고른 설정(τ 0.09, N (19 km, 0.2), ρ 0.25)을 그대로 옮겼을 때의 호출·MAE.
